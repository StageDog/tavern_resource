# 自动更新角色卡

- **作者:** 青空莉想做舞台少女的狗, fannnnnnn5822
- **版本:** 2025/02/11
- **源文件:** [点此跳转](https://github.com/StageDog/tavern_resource/tree/main/src)

## 基本使用

在角色卡面板中加载你要自动更新的角色卡, 将这个脚本添加到酒馆助手 "角色脚本" 中, 编辑脚本, 在`变量列表`中填入角色卡名称、角色卡链接和更新日志链接.

例如:

```yaml
{
  角色卡名称: 自动更新角色卡示例
  角色卡链接: https://testingcf.jsdelivr.net/gh/StageDog/tavern_resource/src/酒馆助手/自动更新角色卡/示例角色卡.png
  更新日志链接: https://testingcf.jsdelivr.net/gh/StageDog/tavern_resource/src/酒馆助手/自动更新角色卡/示例更新日志.md
}
```

其中,

- 角色卡名称要和角色卡在酒馆中的名称一样, 确定好后不能再更改
- 角色卡链接和更新日志链接必须是固定的, 而且访问的是最新版本角色卡和更新日志文件.

比如, 你可以把角色卡和更新日志文件上传到 github, 然后使用 `https://testingcf.jsdelivr.net/gh/用户名/仓库名/文件路径` 作为角色卡链接和更新日志链接 (不清楚怎么做可以搜索一下或者问 AI).

而更新日志应该按下面这样填写:

```md
# 更新日志

## 这里填的会是角色卡版本号, 最上面一个版本是最新版本

- 最新版本更新了啥……

## 新春版

- 这个版本更新了啥……

## 1.0.0

- 这个版本更新了啥……
```

这样一来, 只要你更新链接所访问到的角色卡和更新日志, 玩家就能在酒馆中直接更新角色卡, 不需要去帖子查看更新, 不需要再下载、导入新角色卡了!

## 保证极端情况角色卡更新也有效

不过 jsDelivr 这类网址会缓存最新版本文件, 12h 后才失效, 而更新日志和角色卡两个文件各缓存各的. 于是会出现: 更新日志已经是新版, 玩家点更新却拉到旧角色卡.

如果你确定要使用 jsDelivr 而不是自己的什么云盘, 可以选择以下一种方法, 来保证在极端情况下玩家也能正常更新角色卡:

### 法一：为角色卡和更新日志同时添加版本号

在酒馆网页-角色卡侧边栏-点击地球仪图标 (也就是角色卡世界书) 左边的书籍图标, 在打开的窗口中展开“创作者的元数据”，在“角色版本”里填写与更新日志最新一个 `##` 一模一样的版本号. 比如, 如果是 `## 新春版`, 你就在“角色版本”里填写 `新春版`.

这样, 脚本在更新时会检测角色卡版本号和更新日志里的版本号是不是一样的, 然后才更新.

### 法二：用固定版本号获取角色卡

给仓库打上与角色卡版本一模一样的 tag (如 `v1.2.0`), 然后填写角色卡链接时在仓库名后面加上 `@{version}`样, 如 `https://testingcf.jsdelivr.net/gh/StageDog/tavern_resource@{version}/src/酒馆助手/自动更新角色卡/示例角色卡.png`.

这样, 脚本会在更新时自动替换 `{version}` 为最新版本号, 保证是从固定的版本号获取角色卡数据.
